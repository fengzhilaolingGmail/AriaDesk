# AriaDesk 功能分析与实现方案

> Wails (Go) 桌面端 aria2 管理器 —— 功能分析、实现步骤与补充设计
> 协议范围：仅 JSON-RPC over HTTP（aria2 默认 6800 端口），不使用 WebSocket

---

## 1. 项目概述

- **技术栈**：Go + Wails v2 + **Vue 3 + Vite**（前端技术选型已确定，不使用 React）
- **目标平台**：Windows 10/11（后续可扩展 macOS/Linux）
- **核心定位**：aria2 的"安装器 + 启动器 + 轻量 WebUI"，把"装 aria2、配 token、敲命令"全部变成 GUI 操作

### 前端技术约定（Vue 3 + Vite）

- **构建工具**：Vite（Wails 官方 Vue 模板内置，dev 时由 Wails 托管、支持 HMR）
- **初始化命令**：`wails init -n AriaDesk -t vue`（生成 Vue 3 + Vite 模板）
- **语法风格**：Composition API + `<script setup>`
- **状态管理**：Pinia（管理连接状态、设置、任务列表等全局状态）
- **UI 组件库**：Element Plus（桌面端工具类界面成熟稳定），但必须定制主题（见下方设计规范，禁止默认主题直出）；图标用 `@element-plus/icons-vue`
- **与 Go 交互**：通过 Wails 自动生成的 `wailsjs/go/main/App.js` 绑定调用 Go 方法；Go → 前端推送用 `runtime.EventsEmit` + 前端 `EventsOn` 监听（轮询数据、状态变更）

### 前端视觉设计规范（design-taste-frontend 适配）

**Design Read**：Windows 桌面工具控制台（非营销落地页），Linear 式克制语言，Element Plus 定制主题 + 中性灰底 + 单一饱和蓝强调。
**Dials**：`DESIGN_VARIANCE: 4` / `MOTION_INTENSITY: 3` / `VISUAL_DENSITY: 6`（工具界面以可信、低打扰为先，数据密度中高）。

#### 色彩（单强调色锁定）

| 角色 | 值 | 说明 |
|---|---|---|
| Primary | `#2E62F6`（接近 blue-600） | 全站唯一强调色，仅用于主按钮、选中态、链接、进行中任务 |
| Success | `#16A34A` | 语义色：已连接状态、下载完成，不与 primary 混用 |
| Warning / Danger | `#D97706` / `#DC2626` | 纯语义场景（删除确认、错误提示） |
| 中性色 | Zinc 家族（light）/ 近黑 zinc-950（dark） | 全站只用这一套灰，不冷暖混用；禁用纯黑 `#000` |
| 禁用 | 紫色渐变、霓虹发光、mesh 渐变背景 | AI 套版痕迹，一律禁止 |

暗色模式：跟随系统 `prefers-color-scheme` + 设置页手动切换，全应用单一主题族，不允许页面中部突然切浅色块。

#### 字体

- **中文**：系统栈 `system-ui, "Microsoft YaHei", "PingFang SC", sans-serif`（桌面端无需引入中文字体文件）
- **拉丁/界面英文**：默认跟随系统栈，不引入 Inter 作为默认
- **数字（速率、进度、任务数）**：`JetBrains Mono` 等宽字体，自托管 `@font-face` + `font-display: swap`，保证统计卡片与任务列表数字列对齐（DENSITY 6 的 cockpit 规则）

#### 形状与布局

- 圆角锁定一套规则并全局一致：卡片/输入框 8px，按钮 6px，标签 pill 全圆角；不允许圆按钮配方卡片的混用
- 统计卡片四等分网格（参考图），任务列表用 `divide-y` 分行而非逐项卡片包裹
- 页面内容区 `max-w-[1200px]` 居中；工具窗口无 hero 概念，首屏直接是连接区 + 统计卡片

#### 动效（MOTION 3，全部可被 `prefers-reduced-motion` 关闭）

- 仅允许：CSS transition 0.2s（按钮 hover/active、`scale-[0.98]` 按压反馈）、统计数字变化过渡、任务列表行进入的 stagger fade（≤ 200ms）
- 禁止：滚动劫持、视差、无限循环装饰动画、GSAP 大屏动效；动效必须"有动机"（反馈用户操作或状态变更），做不到就说明不需要

#### 状态完整性（强制）

每个界面必须有完整状态周期，不允许只画成功态：

| 状态 | 实现 |
|---|---|
| Loading | 骨架屏（形状对齐最终布局），禁用通用转圈 spinner |
| Empty | 参考图空态：图标 + "此列表中没有下载任务" + 新建任务引导按钮 |
| Error | 行内错误（表单）+ 连接失败横幅（RPC 不可达时连接区显示红色提示与重试） |
| aria2 未安装 | 首页整体替换为安装引导卡片（功能一） |

#### 文案纪律

- 零装饰性文案，按钮标签 ≤ 4 字优先（"新建任务"优于"新建下载任务"，最终对齐参考图）
- 无版本号标签、无状态装饰圆点（状态圆点仅用于真实的连接语义状态，全页最多一处）
- 连接徽标三种语义色有真实含义：灰=未安装、红=未连接、绿=已连接（N 个进行中），属于"真实语义状态"的合法用途

## 2. 功能一：检测与安装 aria2

### 2.1 检测逻辑

1. 执行 `aria2c --version`，解析输出中的 `aria2 version 1.36.0` 得到版本号。
2. **查找顺序**（关键，很多坑在这里）：
   - 直接 `exec.Command("aria2c", "--version")` —— 依赖 PATH；
   - 若失败，**继续搜索常见安装路径**，因为 winget 安装后**父进程的 PATH 环境变量不会刷新**：
     - `%LOCALAPPDATA%\Microsoft\WinGet\Packages\aria2.aria2_*\aria2c.exe`（portable 包，winget 默认）
     - `%LOCALAPPDATA%\Microsoft\WinGet\Links\aria2c.exe`（存在 Links shim 的情况）
     - `C:\Program Files\aria2\aria2c.exe`、`C:\Program Files (x86)\aria2\aria2c.exe`
   - 找到路径后缓存到 settings.json，之后直接用绝对路径执行。
3. 前端状态机：`未安装` / `已安装 (v1.36.0)` / `检测中…` / `安装中…`。
4. 检测结果随"连接/刷新"自动更新。

### 2.2 安装逻辑与权限分析

执行命令：`winget install aria2.aria2`

**权限结论：默认不需要管理员权限。**

| 场景 | 是否需要 UAC 提权 | 说明 |
|---|---|---|
| `winget install aria2.aria2`（默认） | **否** | aria2 的 winget 包是 **portable 包**，装到 `%LOCALAPPDATA%\Microsoft\WinGet\Packages`，仅当前用户可用 |
| `winget install --scope machine` | **是** | 需要 UAC 提权，弹出 UAC 窗口 |
| 公司机器策略限制 winget | 可能失败 | 需兜底：引导用户手动下载或报错提示 |

因此**保持默认 per-user 安装即可，程序不需要以管理员身份运行**。前端提示用户"即将弹出 winget 安装窗口，按提示完成安装"。

### 2.3 安装实现要点

```go
// 建议参数
winget install --id aria2.aria2 --exact --accept-source-agreements --accept-package-agreements
```

- `--accept-source-agreements --accept-package-agreements`：首次使用 winget 时否则会卡在交互式协议确认，GUI 程序必加。
- 用 `cmd /c` 或直接 exec 均可；winget 安装过程有进度输出，可捕获 stdout 显示进度。
- 安装前检查 `winget --version` 是否存在；不存在则提示（Win10 老版本需引导用户安装"应用安装程序"）。
- 安装完成后：重新执行检测逻辑（搜 winget Packages 目录拿绝对路径）→ 自动填充版本 → 提示可以启动。

## 3. 功能二：设置（开机自启 + 关闭行为）

### 3.1 配置持久化

`settings.json` 结构（启动时加载，修改即保存）：

```json
{
  "aria2Path": "",
  "rpcPort": 6800,
  "downloadDir": "C:\\Downloads",
  "autoStartAria2": true,
  "autoStartApp": false,
  "closeToTray": true
}
```

### 3.2 开机自启动

**方案：写注册表 Run 键（推荐，无需管理员权限）**

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
AriaDesk = "C:\path\to\Ariadesk.exe" --minimized
```

- 用户级（HKCU），完全不需要管理员权限，这正是选它的原因。
- 备选方案：Task Scheduler（计划任务，可设"无论用户是否登录"），复杂度更高，v1 不建议。
- 实现：Go 用 `golang.org/x/sys/windows/registry` 包。
- `--minimized` 参数：自启动时最小化到托盘，不打扰用户。

### 3.3 关闭按钮行为（退出 vs 最小化到托盘）

**前置事实：Wails v2 没有内置系统托盘**，需要第三方库：

- 推荐 `github.com/energye/systray`（getlantern/systray 的活跃 fork，Windows 兼容性好），在 Go 侧启动托盘消息循环。

实现方式：

1. 实现 `OnBeforeClose(ctx) bool`：当设置 `closeToTray=true` 时返回 `true` **阻止关闭**，并调用 `runtime.WindowHide()` 隐藏到托盘；返回 `false` 则正常退出。
2. 托盘菜单：
   - 显示主窗口（`runtime.WindowShow` + `runtime.WindowUnminimise`）
   - 启动 / 停止 aria2
   - 打开下载目录（`cmd /c start <dir>`）
   - 退出（真正 `os.Exit`）

3. 窗口标题栏最小化按钮保持正常最小化，只有点"×"才触发 closeToTray 逻辑。

## 4. 功能三：启动 aria2 与密钥管理

### 4.1 token.pass 加密存储

需求：设置界面输入 RPC 密钥 → 生成 `token.pass` 文件（加密存储）→ 启动 aria2 时自动读取。

**推荐方案：Windows DPAPI（`CryptProtectData`），以 `CurrentUser` 作用域加密。**

| 方案 | 优点 | 缺点 |
|---|---|---|
| **DPAPI（推荐）** | 系统级安全、密钥由 Windows 托管无需自己保管、Go 实现简单（`syscall.NewLazyDLL("crypt32.dll")` 调 `CryptProtectData`） | 仅 Windows（当前项目无所谓）；同用户任意进程可解（威胁模型可接受） |
| AES-256-GCM + 本地派生密钥 | 跨平台 | 密钥落盘问题绕不开，自己实现容易出漏洞 |
| 明文 | 简单 | 不安全，排除 |

- DPAPI `CurrentUser` 作用域：密文只能被**同一 Windows 用户**在本机还原，符合"桌面端本地管理"场景。
- 实现 `internal/secret` 包：`Save(token string) error` / `Load() (string, error)`，`token.pass` 存 `%APPDATA%\AriaDesk\token.pass`。
- **token 为空时的处理**：未配置过密钥时自动生成一个随机 token（如 16 字节随机 hex），保证"零配置可用"，前端设置框默认显示掩码，提供"重新生成"按钮。

### 4.2 启动 aria2

用户给的命令：

```
aria2c --enable-rpc --rpc-allow-origin-all=true --rpc-secret=YOUR_SECRET --daemon=true
```

**修正建议（重要）：Windows 下不建议用 `--daemon=true`。**

- `--daemon` 会让进程 fork 脱离，Go 侧拿不到可靠的 PID，无法做"停止 aria2"、"进程存活监控"、"退出时清理"。
- 替代做法：不带 `--daemon`，用 `exec.Cmd` + `SysProcAttr{HideWindow: true, CreationFlags: CREATE_NEW_PROCESS_GROUP}` 启动，**隐藏控制台黑窗口**，Go 持有 `*exec.Cmd`，需要停止时：
  1. 优先调 RPC `aria2.shutdown`（优雅退出，会先保存会话）；
  2. 超时后 `cmd.Process.Kill()` 兜底。

完整启动参数（v1 建议）：

```
aria2c
  --enable-rpc
  --rpc-listen-port=<settings.rpcPort, 默认 6800>
  --rpc-secret=<从 token.pass 解密>
  --rpc-allow-origin-all=true
  --rpc-listen-all=false            # 仅本机，安全
  --dir=<settings.downloadDir>
  --input-file=<session.txt>        # 恢复上次任务
  --save-session=<session.txt>      # 定时保存会话
  --save-session-interval=60
  --log=<aria2.log> --log-level=warn
  --max-concurrent-downloads=5      # 可按需暴露到设置页
```

### 4.3 启动入口

- **手动**：首页/管理页"启动 aria2"按钮。
- **自动**：设置项 `autoStartAria2=true` 时，App 启动后延迟 1~2s 自动拉起（等待 UI ready）。
- 启动前校验：
  1. aria2 已安装（功能一）；
  2. 端口未被占用（见 §6 补充功能）；
  3. 下载目录存在（见下）。

### 4.4 默认下载目录设置

- 设置页输入框 + "浏览…"按钮（Wails `runtime.BrowserOpenDirectory`？v2 提供 `runtime.BrowserOpenDirectory`  Dialog 选择目录：`runtime.SaveFileDialog` / 专门有 `runtime.BrowserOpenDirectory`？实际 API 是 `runtime.OpenDirectoryDialog`）。
- 保存前校验：`os.Stat` 确认目录存在且可写（尝试创建一个临时文件再删除）。
- 默认值：`%USERPROFILE%\Downloads`。
- 修改下载目录**只影响之后新建的任务**；aria2 运行中修改 `--dir` 需要 RPC `aria2.changeGlobalOption`，v1 简化处理为"修改后提示重启 aria2 生效"，或直接停启 aria2。

## 5. 功能四：首页（按参考图实现）

页面结构完全对齐参考图，仅一处需求变更：**RPC 密钥输入框改为只读 + 自动填充**（从 token.pass 解密读入，掩码显示，旁边"重新生成"按钮在设置页）。

### 5.1 连接区

```
[RPC 地址: 只读 localhost] [端口: 6800 可改] [Token: •••• 只读自动填充] [连接/刷新]  [● 已连接 (0 个进行中)]
```

- 连接/刷新 → 调 `aria2.getVersion` 验证连通性与 token 正确性。
- 状态徽标三种：`未安装 aria2`（灰）/ `未连接`（红）/ `已连接 (N 个进行中)`（绿）。
- RPC 地址固定 localhost（本项目只管本机 aria2），端口可配置。

### 5.2 统计卡片（4 张）

数据来自 `aria2.getGlobalStat`，前端轮询（建议 1s）：

| 卡片 | 字段 | 说明 |
|---|---|---|
| 当前下载速率 | `downloadSpeed` | B/s → 前端格式化为 KB/s、MB/s |
| 当前上传速率 | `uploadSpeed` | 同上 |
| 进行中任务 | `numActive` | |
| 等待/已暂停 | `numWaiting` + `numStoppedTotal` 或按 tab 实际计数 | 图上是"等待 / 已暂停"，建议拆为 `numWaiting`（等待）+ 暂停数（由 tellWaiting 统计 status=pause 得出） |

### 5.3 任务列表

Tab：`进行中` / `等待中 / 暂停` / `已完成 / 停止`，对应 RPC：

| Tab | RPC 方法 |
|---|---|
| 进行中 | `aria2.tellActive` |
| 等待中 / 暂停 | `aria2.tellWaiting(0, 1000)`，前端按 `status` 过滤显示（waiting / paused） |
| 已完成 / 停止 | `aria2.tellStopped(0, 100)`（倒序） |

每行显示：文件名（`files[0].path` 或 `bittorrent.info.name`）、进度条（`completedLength/totalLength`）、速率、已连接数（`connections`）、操作按钮（暂停/恢复/删除/打开目录）。

顶部操作：

| 按钮 | RPC | 说明 |
|---|---|---|
| ＋ 新建下载任务 | `aria2.addUri` | 弹窗输入 URL（http/https/磁力链 magnet:）；**建议补充**：支持种子文件 `.torrent`（`aria2.addTorrent`，base64 传入） |
| 暂停全部 | `aria2.pauseAll` | |
| 恢复全部 | `aria2.unpauseAll` | |
| 清理已完成 | `aria2.purgeDownloadResult` | 仅清理"已完成/停止"记录 |

### 5.4 JSON-RPC 客户端设计（Go 侧）

统一走一个 `rpc.Client`：

```go
// 请求格式 (JSON-RPC 2.0 over HTTP POST)
POST http://localhost:6800/jsonrpc
{
  "jsonrpc": "2.0",
  "id": "ariaDesk",
  "method": "aria2.getGlobalStat",
  "params": ["token:YOUR_SECRET"]
}
```

- token 作为 `params` 第一个元素：`token:<secret>`（aria2 规定）。
- Go 用 `net/http` + `encoding/json` 实现即可，无需第三方 RPC 库。
- 所有 RPC 方法在 `app.go` 暴露为 Wails 绑定方法（`GetVersion` / `GetGlobalStat` / `TellActive` / `AddURI` …），前端 `window.go.main.App.XXX` 调用。
- 轮询在 **Go 侧**用 `time.Ticker` 做，通过 `runtime.EventsEmit("stat", data)` 推给前端，比前端 setInterval 调绑定方法更稳、更好控制（aria2 未启动时自动降频或暂停轮询）。

## 6. 补充功能（你未提到但建议实现）

按优先级排序：

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| 1 | **端口占用检测** | 启动 aria2 前检查 6800 是否被占用；若被占，先尝试 RPC 探测是不是"自己上次启动的 aria2 还活着"，是则直接复用连接，否则报错提示 | P0 |
| 2 | **aria2 进程存活监控** | Go 持有进程句柄，`cmd.Wait()` 返回即进程退出 → 前端状态变"未连接"并提示；可选自动重启 | P0 |
| 3 | **单实例运行** | 用 Windows Mutex（`kernel32!CreateMutexW`）保证只开一个 AriaDesk，二次启动时激活已有窗口 | P0 |
| 4 | **退出时优雅停止 aria2** | App 退出时调 `aria2.shutdown`（`--save-session` 已由参数保证），避免残留 aria2c 进程 | P1 |
| 5 | **下载完成通知** | 轮询中对比 `tellStopped` 出现 `status=complete` 的新任务 → Windows Toast 通知（`github.com/go-toast/toast`） | P1 |
| 6 | **单个任务操作** | 每行的暂停（`aria2.pause`）/ 恢复（`aria2.unpause`）/ 删除（`aria2.remove` + `aria2.removeDownloadResult`）/ 打开所在文件夹（`explorer /select,<path>`） | P1 |

## 9. 风险与注意点汇总

- **PATH 不刷新**：winget 装完后必须搜索固定目录缓存 aria2c 绝对路径，不能指望 PATH。
- **winget 不存在**：老版 Win10 无 winget，需要友好降级提示。
- **Wails 无内置托盘**：引入 energye/systray，注意它有自己的消息循环，需要在独立 goroutine 启动并处理好与 Wails 窗口生命周期的协同。
- **不要以管理员身份运行整个 App**：DPAPI(Run 键、per-user winget)都不需要提权，管理员运行反而导致自启/加密上下文错位（不同用户上下文）。
- **`--daemon` 不用**：Windows 下用隐藏控制台窗口托管进程，换取可控的停止与监控能力。
- **RPC 安全**：`--rpc-listen-all=false` 只监听 127.0.0.1，token 必配；`--rpc-allow-origin-all=true` 只影响浏览器同源限制，本桌面端无跨域问题，可保留可去掉。
- **token.pass 丢失**：提示重新生成（旧任务记录不受影响，只是 RPC 密钥更换）。
