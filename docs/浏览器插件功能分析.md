# AriaDesk 浏览器插件功能分析

> 浏览器插件 ↔ AriaDesk 联动下载：拦截浏览器下载请求（普通链接 / BT），推送到桌面软件自动下载
> 通信端口范围：20000 ~ 20005（仅 loopback）
> 本文档仅做功能分析与方案选型，不含实现

---

## 1. 需求分解

| # | 需求 | 说明 |
|---|------|------|
| 1 | 普通下载链接接管 | 浏览器中点击下载链接时，取消浏览器自身下载，把 URL 推送到 AriaDesk，由 aria2 下载 |
| 2 | BT 支持 | magnet: 磁力链接、.torrent 种子文件两种形态都要能推送 |
| 3 | 端口范围 | App 在 20000~20005 内监听本地 HTTP 服务，供插件调用 |
| 4 | 自动下载 | 推送后无需人工干预，任务直接进入 aria2 队列 |

隐含需求（分析推导，需确认）：

- **插件主动发现端口**：端口之所以是"范围"，是因为 20000 可能被占用，App 要向后退让；插件侧需要一种方式知道当前用的是哪个端口（见 §4.2）。
- **鉴权**：本地 HTTP 端口任何网页都能 POST（drive-by 攻击面），必须有配对 token（见 §6）。
- **Cookie 场景**：PT 站、网盘等需登录的下载，aria2 直接拉 URL 会 401/403，插件需要把 Cookie/UA/Referer 一并传过来；.torrent 链接更极端——必须由插件带 Cookie 抓下种子文件本体再推送字节（见 §5.3）。

## 2. 现有项目盘点（可复用能力）

| 能力 | 位置 | 复用方式 |
|------|------|----------|
| `client.AddURI(ctx, uri, options)` | `internal/rpc/client.go:134` | 普通链接、magnet 链接直接复用；options 可带 `header`（Cookie/UA/Referer）、`out`（文件名） |
| `client.AddTorrent(ctx, data, options)` | `internal/rpc/client.go:144` | 种子字节 base64 提交，直接复用 |
| `dirOption()` 下载目录注入 | `app.go:819` | 插件任务同样走当前设置的下载目录 |
| aria2 生命周期管理 | `app.go` StartAria2 / StopAria2 / 端口占用复用探测 | 收到推送时 aria2 未运行，可自动拉起 |
| DPAPI 加密存 token | `internal/secret/secret.go` | 插件配对 token 可用同一套机制单独存一个文件（如 `ext.pass`），与 aria2 rpc-secret 隔离 |
| 设置持久化与校验 | `internal/config/config.go` | 新增浏览器联动开关等字段 |
| 完成通知 / 历史 | `app.go:1104` checkCompleted、toast | 插件推来的任务自动享有完成通知和历史记录，磁力链 FollowedBy 元数据任务已被正确排除 |
| 单实例运行 | `main.go:29` ensureSingleInstance | 保证 HTTP 服务只被一个实例绑定，无多实例抢端口问题 |

关键事实：

- aria2 的 RPC 端口（默认 6800，可配）**不应**直接暴露给插件——用户明确要求 20000~20005，且让插件持有 aria2 rpc-secret 会扩大密钥泄露面。因此采用 **App 内嵌一个独立 HTTP 服务做中转** 的架构，而不是插件直连 aria2。
- App 是 Windows 单实例托盘程序，常驻运行，适合做本地服务宿主。

## 3. 方案选型

### 3.1 候选通道对比

| 方案 | 原理 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. App 内嵌 HTTP 服务（推荐）** | App 监听 127.0.0.1:20000~20005，插件 fetch 调用 | 实现简单；插件端就是普通 fetch；天然匹配用户的端口要求；App 不在时插件能明确报"未连接" | 需要处理鉴权与端口协商 | ✅ 采用 |
| B. Native Messaging | 注册表注册原生消息宿主，浏览器拉起进程走 stdio | 无端口、无鉴权问题 | 每次通信可拉起新进程（与单实例逻辑冲突）；安装要写注册表；调试困难；不符合端口范围要求 | ❌ |
| C. 自定义协议 `ariadesk://` | 插件跳转自定义协议唤起 App | 零服务 | 浏览器每次弹确认框；URL 长度限制放不下 base64 种子；无法回传执行结果 | ❌ |
| D. 插件直连 aria2 RPC (6800) | 插件持有 rpc-secret 直接 addUri | App 零改动 | 违背端口要求；rpc-secret 泄露面扩大；插件拿不到 App 层能力（自动拉起、通知、去重） | ❌ |

### 3.2 推荐架构

```
浏览器插件 (MV3)
  ├─ downloads API 拦截普通下载
  ├─ content script 拦截 magnet: 点击
  └─ context menu "用 AriaDesk 下载"
        │  HTTP + 配对 token 头
        ▼
AriaDesk App（新增 internal/extsrv 包）
  ├─ 端口协商：20000 → 20005 顺序探测绑定
  ├─ 鉴权中间件
  ├─ POST /api/download  → rpc.AddURI（带 header/out/dir）
  ├─ POST /api/torrent   → rpc.AddTorrent（base64）
  └─ aria2 未运行 → 自动 StartAria2 后重试
        ▼
     aria2 (6800 RPC, token 不离开 App)
```

## 4. App 侧功能分析

### 4.1 新增模块 `internal/extsrv`

职责：

- 启动/停止 HTTP 服务，挂到 App 生命周期（`startup` 启动、`cleanup` 停止）
- 端口协商：从 20000 起依次尝试 `net.Listen("tcp", "127.0.0.1:PORT")`，占用则试下一个，直到 20005；全部占用则记录日志、UI 提示"浏览器联动端口被占"，功能降级但不影响主程序
- 只绑 `127.0.0.1`：不触发 Windows 防火墙弹窗（绑 0.0.0.0 才会），也不暴露给局域网

### 4.2 端口发现协议（插件如何找到 App）

插件无法读本地文件，只能靠**扫描**：

- App 提供 `GET /api/ping`，无需鉴权（或仅返回非敏感信息），响应：
  ```json
  { "app": "AriaDesk", "version": "0.1.0", "api": 1 }
  ```
- 插件启动时/连接失败时顺序探测 20000→20005，命中含 `app: "AriaDesk"` 的端口即锁定，缓存到 `storage.local`
- `api` 字段用于日后协议升级时插件做兼容判断

### 4.3 API 设计（v1）

| 方法 | 路径 | 鉴权 | 请求体 | 响应 |
|------|------|------|--------|------|
| GET | `/api/ping` | 无 | — | `{app, version, api}` |
| POST | `/api/download` | token | `{url, filename?, referer?, cookies?, userAgent?}` | `{gid}` 或 `{error}` |
| POST | `/api/torrent` | token | `{name, dataBase64}` | `{gid}` 或 `{error}` |

行为约定：

- `magnet:` 开头的 URL 走 `/api/download`，内部同样调 `AddURI`（aria2 原生支持磁力）
- `cookies`/`userAgent`/`referer` 拼装为 aria2 的 `header` option；`filename` 映射 `out` option；目录仍用 `dirOption()`
- 收到请求时 aria2 未连接：先尝试 `StartAria2()`（复用现有自动启动逻辑），失败则返回明确错误码（如 `ARIA2_NOT_RUNNING`），插件弹通知"请启动 AriaDesk 的 aria2 服务"
- 请求体大小限制（如 10 MB），防止异常大 base64 种子打爆内存
- 成功后：toast 通知"已接收浏览器下载任务"（复用 go-toast），若窗口开着则 `EventsEmit` 刷新任务列表（现有轮询 1s 已能覆盖，可不额外发事件）

### 4.4 设置项新增

`config.Settings` 增加：

| 字段 | 默认 | 说明 |
|------|------|------|
| `BrowserExtEnabled` | true | 浏览器联动总开关，关闭即停掉 HTTP 服务 |
| （token 不入 settings） | — | 配对 token 单独走 DPAPI 存 `ext.pass`，UI 复用现有"显示/重新生成 token"交互模式 |

设置页需新增一块"浏览器插件"：开关、当前实际监听端口展示、token 显示/重新生成、插件安装引导链接。**重新生成 token 后插件侧必须重新填写**，这点要在 UI 文案里写清楚。

## 5. 插件侧功能分析（Manifest V3，Chrome/Edge 优先，兼容 Firefox）

### 5.1 模块拆解

| 模块 | 技术 | 职责 |
|------|------|------|
| background (service worker) | MV3 SW | 端口扫描与缓存、token 存储、向 App 发请求、结果通知（chrome.notifications） |
| 下载拦截 | `chrome.downloads.onCreated` + `downloads.cancel/erase` | 普通下载接管：取消浏览器下载 → 提取 URL/Referer → POST /api/download |
| 磁力拦截 | content script 监听 click | `a[href^="magnet:"]` 点击 `preventDefault` → 发 background 推送（downloads API 捕获不到 magnet） |
| 右键菜单 | `chrome.contextMenus` | "用 AriaDesk 下载"：兜底手段，对链接/种子链接手动推送 |
| popup | 状态页 | 连接状态（已连接端口 / 未连接）、开关、跳转设置 |
| options 页 | 设置 | token 填写、接管开关、过滤规则、黑名单 |

### 5.2 普通下载接管的边界问题

- **不能无脑全接管**：小文件（图片另存、几 KB 的配置文件）接管体验差。需要过滤规则：按文件大小阈值（onCreated 阶段拿不到大小时可按扩展名/MIME 粗筛）、按扩展名白/黑名单、按域名黑名单
- **拦截失败回退**：推送 App 失败（未连接/超时）时，应恢复浏览器自身下载（重新 `downloads.download` 同一 URL），不能让用户"点了没反应"
- **重复拦截防护**：自己回退触发的 `downloads.download` 会再次触发 onCreated，需要标记跳过
- `chrome.downloads` 需要 `"downloads"` 权限；拦截确定文件名前的时机用 `onDeterminingFilename` 可拿文件名，但 MV3 下建议用 onCreated 尽早取消避免浏览器先落盘

### 5.3 BT 两类形态的处理

| 形态 | 捕获方式 | 推送方式 |
|------|----------|----------|
| magnet: 链接 | content script 点击拦截 / 右键菜单 | URL 直接 POST /api/download（aria2 原生解析磁力） |
| .torrent 文件链接 | downloads API 拦截 **不行**（需登录态）→ 插件内 `fetch(url, {credentials:'include'})` 带 Cookie 抓字节 | base64 POST /api/torrent |
| 本地 .torrent 文件 | 不在本需求范围（App 已有"选择种子文件"） | — |

关键点：**PT/私有站的 .torrent 必须由插件带 Cookie 抓取**，把 URL 丢给 aria2 拉取会 403。公共站的 .torrent URL 可以降级为直接推送 URL。

### 5.4 插件设置项

- 配对 token（必填，否则所有请求 401）
- 接管总开关 + "每次询问还是直接下载"
- 文件大小阈值、扩展名过滤、域名黑名单
- 推送失败时是否回退浏览器下载（默认开）

## 6. 安全分析

| 威胁 | 缓解 |
|------|------|
| 恶意网页向 127.0.0.1:20000 POST 伪造下载（drive-by） | 配对 token 放自定义头（如 `X-AriaDesk-Token`）：网页发起带自定义头的跨域请求必先过 CORS 预检，服务端**不响应任何预检**即天然免疫；插件从 service worker 发请求不受 CORS 限制 |
| 局域网/其他机器调用 | 只绑 127.0.0.1 |
| token 落盘泄露 | DPAPI 加密存储（复用 secret 包），插件侧存 `storage.local`（浏览器 Profile 内） |
| 端口扫描信息泄露 | `/api/ping` 只暴露应用名和版本，不暴露路径、用户名等 |
| 恶意大请求 | 请求体上限、JSON 严格解析、URL scheme 白名单（http/https/magnet） |
| 插件端 token 填错暴力尝试 | 本地面向单用户，风险低；可加简单速率限制（可选，v1 不做） |

## 7. 异常与边界场景清单

| 场景 | 预期行为 |
|------|----------|
| App 未运行 | 插件 popup 显示"未连接"，推送时报错通知，提供重试 |
| aria2 未启动 | App 收到推送自动拉起；拉起失败返回错误码 |
| 20000~20005 全被占用 | App 日志 + 设置页提示，主功能不受影响 |
| token 不匹配 | 401，插件提示"请检查配对 token" |
| 插件重复推送同一 URL | aria2 允许同 URL 多任务（行为与 App 内手动添加一致），v1 不做去重；如需去重可在 App 侧比对 active+waiting 的 URL（列入二期） |
| aria2 反回错误（URL 非法等） | 错误透传给插件，通知用户 |
| App 升级后协议变化 | `api` 版本号字段兜底，插件提示升级 |

## 9. 实施步骤建议（后续开发顺序）

1. **App 侧先行**：`internal/extsrv`（监听 + 端口协商 + ping）、token 生成/存储、设置项与 UI
2. 打通 `POST /api/download` → `AddURI`（含 aria2 未运行自动拉起）
3. 打通 `POST /api/torrent` → `AddTorrent`
4. **插件侧脚手架**：MV3 manifest、端口扫描、token 配置、popup 状态
5. 右键菜单推送（最快可用的 MVP 路径）
6. downloads API 接管 + 过滤规则 + 失败回退
7. magnet 点击拦截、.torrent 带 Cookie 抓取
8. 联调边界场景（§7 清单逐项过）
